# 5. Ubiquitous Language

Một trong những nguyên nhân khiến dự án trở nên hỗn loạn là mỗi người gọi cùng một đối tượng bằng một cái tên khác nhau.

Ví dụ:

- Backend gọi là **User**
- Frontend gọi là **Member**
- QA gọi là **Employee**
- Business gọi là **Staff**
- Database gọi là **Account**

Đó là dấu hiệu của một hệ thống thiếu thiết kế.

Trong **Domain-Driven Design (DDD)**, tất cả các thành viên trong dự án phải thống nhất sử dụng **một ngôn ngữ chung**, được gọi là **Ubiquitous Language**.

## Ví dụ Ubiquitous Language

| Thuật ngữ | Ý nghĩa |
|-----------|----------|
| Organization | Doanh nghiệp sử dụng hệ thống |
| Workspace | Không gian làm việc của Organization |
| Member | Người thuộc Workspace |
| Guest | Người được mời vào Workspace |
| Project | Một dự án |
| Task | Một công việc |
| Document | Một tài liệu |
| Folder | Thư mục chứa tài liệu |
| Comment | Bình luận |
| Notification | Thông báo |
| Activity | Nhật ký hoạt động |
| Automation | Workflow tự động |
| AI Assistant | Trợ lý AI |
| Role | Vai trò |
| Permission | Quyền |

> **Quy tắc của chương trình:**  
> Nếu một thuật ngữ chưa được định nghĩa thì **chưa được phép viết code**.

# 6. Business Domain

Đây là bước mà phần lớn lập trình viên chưa từng thực hiện.

Nhiều Junior thường chia project theo bảng dữ liệu:

- User Module
- Task Module
- Project Module

Đó chỉ là cách chia theo **Database**.

Trong DDD, chúng ta chia theo **Business Capability** (năng lực nghiệp vụ).

Đối với **AEOS**, hệ thống sẽ được chia thành các Business Domain sau:

- Identity & Access
- Workspace Management
- Project Management
- Knowledge Management
- Document Management
- Communication
- Notification
- Search
- Automation
- AI Platform
- Analytics
- Audit
- Administration

> **Lưu ý:**  
> Đây **chưa phải Microservice**, mà chỉ là cách doanh nghiệp được phân chia thành các miền nghiệp vụ (Business Domain).

# 7. Bounded Context

Đây là khái niệm quan trọng nhất của **Domain-Driven Design**.

Một Entity có thể xuất hiện ở rất nhiều nơi trong hệ thống.

Ví dụ: **Task**

- Project sử dụng Task
- Notification sử dụng Task
- Analytics sử dụng Task
- AI sử dụng Task

Tuy nhiên, mỗi Domain chỉ cần biết phần dữ liệu mà nó thực sự quan tâm.

## Project Context

- Title
- Description
- Status
- Assignee

## Notification Context

- Task Assigned
- Task Completed

## Analytics Context

- Task Created
- Task Finished
- Duration

## AI Context

- Summary
- Priority
- Context

Mỗi Domain chỉ biết phần dữ liệu mà mình cần.

Đó chính là **Bounded Context**.

# 8. Domain Event

Một Senior không suy nghĩ theo CRUD.

Senior suy nghĩ theo **Event**.

Thay vì:

```http
POST /projects
```

Họ nghĩ:

```
Project Created
```

Thay vì:

```http
PUT /tasks
```

Họ nghĩ:

```
Task Assigned
Task Completed
Task Archived
```

Thay vì:

```http
POST /documents
```

Họ nghĩ:

```
Document Uploaded
```

Đây chính là tư duy **Event-Driven Architecture**.

Khi hệ thống phát triển lớn hơn, các thành phần như:

- Notification
- Analytics
- Audit
- AI
- Search
- Workflow

chỉ cần **lắng nghe Event** thay vì phụ thuộc trực tiếp vào nhau.

# 9. Command và Event

Đây là hai khái niệm rất dễ bị nhầm lẫn.

## Command

Command là **yêu cầu hệ thống thực hiện một hành động**.

Ví dụ:

- Create Project
- Assign Task
- Upload Document

Sau khi Command được xử lý thành công, hệ thống sẽ sinh ra một hoặc nhiều **Domain Event**.

## Event

Ví dụ:

- Project Created
- Task Assigned
- Document Uploaded

Các Event này tiếp tục kích hoạt những Event khác.

Ví dụ:

```text
Document Uploaded
        │
        ▼
OCR Started
        │
        ▼
Embedding Generated
        │
        ▼
Search Indexed
        │
        ▼
AI Knowledge Updated
        │
        ▼
Notification Sent
```

Đây được gọi là **Event Chaining**.

# 10. Actor

Trong phần lớn các dự án nhỏ, Actor thường chỉ có:

- User

Điều đó là chưa đủ đối với một hệ thống Enterprise.

Trong **AEOS**, Actor bao gồm:

- Owner
- Admin
- Member
- Guest
- AI Agent
- Scheduler
- Webhook
- External System
- System

Việc định nghĩa đầy đủ các Actor ngay từ đầu giúp hệ thống:

- Dễ mở rộng
- Dễ phân quyền
- Dễ tích hợp với hệ thống bên ngoài
- Hỗ trợ Automation và AI ngay từ kiến trúc ban đầu
- Giảm phụ thuộc giữa các thành phần trong hệ thống
